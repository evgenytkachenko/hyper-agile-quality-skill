# hyper-agile-quality-skill v0.1.0-beta

First public pre-release (Python package version `0.1.0b0`). Commands, file formats and output
may change before a stable release. MIT License.

## What you can do

- **Investigate an escaped defect from local evidence.** Put issue records, requirements, code
  and fix changes, test cases, JUnit XML results, CI notes and release records in a case folder
  (`haq init` creates a template; `haq check-case` lists what is there and what is missing).
- **Let your coding agent answer, with every answer checked.** The included agent skill drives
  `haq investigate --answers-dir`: the agent answers three steps (traceability, testing and
  release evidence, hypotheses and proposals), and `haq` checks citations, recorded links,
  quotes, test relevance, confidence vocabulary and evidence timing before writing a report.
- **Replay the fictional demo** (`haq demo`, `haq demo --variant missing-evidence`,
  `haq compare`) with scripted answers and no model, to see what the checks do.
- **Record decisions** in `decisions.yaml`, bound to the exact result, and verify them with
  `haq check-decisions`.

## Install

Python 3.12 or later.

```sh
git clone https://github.com/evgenytkachenko/hyper-agile-quality-skill.git
cd hyper-agile-quality-skill
git checkout v0.1.0-beta
python3.12 -m venv .venv && . .venv/bin/activate
pip install .
haq demo
```

Agent skill (for example Claude Code): `cp -R skill/hyper-agile-quality ~/.claude/skills/`, with
`haq` on the agent's PATH. See the README for the answer-exchange workflow.

## Known limitations

- **Experimental: local models through Ollama.** Tested with a mocked HTTP transport and only
  partially exercised with a local model; no live-model investigation has been completed, and
  no claim is made about any model's accuracy, usefulness, speed or memory use.
- **No live connectors.** Evidence must be exported to local files first.
- **The checks are lexical and structural.** They confirm that a cited identifier, link or quote
  exists where an answer says it does; they cannot confirm that the evidence means what the
  answer says. Hypotheses, confidence levels and proposals are the answer source's, not facts.
- **Masking cannot catch every secret.** Credential-like values are masked; secrets in other
  formats and confidential or personal information pass through. Review every input before an
  answer source sees it and every output before you share it.
- `decisions.yaml` checks detect changed or inconsistent files but nothing is signed, so they
  cannot detect a deliberate, consistent rewrite.
- One fictional case and one variant are included; they show behavior, not usefulness on real
  incidents. Some engine rules anticipate English wording only.
